0一句話直覺：AdamW ＝ Adam ＋「解耦」的權重衰減

✘ Adam ＋ L2 正則化把 λθ 加進梯度：gt = ∇f(θt−1) + λθt−1
θt = θt−1 − η · m̂t√v̂t + ε
λθ 也被除以 √v̂ → 每個參數衰減得不一樣
✔ AdamW（解耦的權重衰減）梯度只有損失：gt = ∇f(θt−1)
θt = θt−1 − η(m̂t√v̂t + ε + λθt−1)
λθ 直接作用在參數上 → 每個參數都乘 (1 − ηλ)

符號與前幾課一致：mt、vt 是 Adam 的一階矩、二階矩，m̂t、v̂t 是偏差修正後的估計；η 是學習率，λ 是權重衰減係數。

📜 小故事：一個「看起來一樣」的錯誤

很多人以為「L2 正則化」和「權重衰減」是同一件事。對 SGD 來說確實如此，但洛希洛夫和弗萊堡大學的法蘭克・胡特（Frank Hutter）發現：在 Adam 這類自適應方法裡，兩者並不相等。當時許多框架的 Adam 用 L2 來實作權重衰減，正則化的效果因此大打折扣。

他們的修正非常簡單：把權重衰減從梯度中解耦（decouple），直接作用在參數上。論文題目就叫 Decoupled Weight Decay Regularization。

2019論文發表於 ICLR；AdamW 進入各大框架
今天Transformer 與大型語言模型的標準優化器

1權重衰減是什麼：每一步都把參數乘上 (1 − ηλ)

θt = θt−1 − ηgt − ηλθt−1 = (1 − ηλ)θt−1 − ηgt

用 SGD（η = 0.1）訓練兩個權重：有用的權重 w1，損失是 (w1 − 2)²，梯度會把它撐在 2 附近；沒用的權重 w2，對損失毫無貢獻，梯度永遠是 0。兩者都從 3 出發：

有用的 w₁沒用的 w₂理論值（虛線）
每步乘上 1 − ηλ
w₁ 最後停在 4/(2+λ)
w₂ 第 100 步剩下

💡 對 SGD 而言，權重衰減等價於 L2 正則化：在損失加上 λ2‖θ‖²，梯度多出 λθ，代進 θ − η(∇f + λθ) 就得到上面的式子。所以大家常把兩個名詞混用——但在 Adam 裡就不行了（第 3 節）。

3Adam ＋ L2 的問題：λθ 也被除以 √v̂

兩個參數目前都是 θ = 1，用同樣的 λ。差別只在梯度通常多大：A 的梯度很大，B 的梯度很小。這一步「被往 0 拉」多少？

Adam ＋ L2：衰減量 ≈ ηλθ / √v̂

AdamW：衰減量 = ηλθ

以 η 為單位；長條是對數刻度（每格 10 倍）。√v̂ 取穩定時的近似 √(g² + (λθ)²)。

4模擬：兩個「沒用的」權重，誰被公平地衰減？

A、B 都對損失沒有貢獻（理想上應該衰減到 0），梯度只有雜訊：A 的雜訊很大、B 的很小。都從 θ = 1 出發，η = 0.001、β1 = 0.9、β2 = 0.999，跑 3000 步：

5AdamW 完整演算法與實務用法

綠色那行是 AdamW 的關鍵：λθ 不進入 m、v，而是在最後直接從參數減掉。紅色是 Adam＋L2 的寫法：λθ 混進梯度，之後會被 √v̂ 縮放。

SGD兩者等價
Adam ＋ L2不等價：λθ 被 √v̂ 縮放，梯度大的參數衰減得少
AdamW解耦：每個參數都乘 (1 − ηλ)

PyTorch 用法

  • torch.optim.AdamW(params, lr=1e-3, weight_decay=0.01)：解耦版，weight_decay 預設 0.01。
  • 注意 torch.optim.Adam(..., weight_decay=λ) 是 L2 版本，不是 AdamW。
  • 常見做法：偏差 b、LayerNorm／BatchNorm 的參數不做衰減，只衰減權重矩陣（用 param groups 分開設定）。
  • Transformer／大型語言模型常用 λ 在 0.01～0.1 之間；實際數值要依問題調整。
